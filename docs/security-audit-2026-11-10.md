# Обновление Next.js и аудит безопасности — 10 ноября 2026

Обновлены зависимости проекта и Node.js для сборки. `npm audit --include=dev`
и `npm audit --omit=dev` после обновления не находят известных уязвимостей.
В прикладном API остаются проблемы авторизации, описанные ниже: нулевой результат
npm audit не означает, что приложение безопасно для публичной эксплуатации.

Исходная версия: коммит `cfc9239` репозитория `nozloy/state51`, ветка `main`.
Отсутствовавшая локальная копия восстановлена из этого репозитория.
Изменения подготовлены в ветке `codex/update-next-security-audit`.

### Временный override minimatch

Последний `@typescript-eslint/typescript-estree@8.72.2` требует `minimatch@^10.2.2`.
Для [GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249)
исправление доступно в 11.0.1. Добавлен **только вложенный** override:

```json
{
  "overrides": {
    "@typescript-eslint/typescript-estree": {
      "minimatch": "11.0.1"
    }
  }
}
```

Проверены используемый парсером CommonJS-экспорт `minimatch`, пять вариантов
сопоставления путей, реальный `projectService` с `allowDefaultProject`, линтер
и TypeScript. Эта замена выходит за исходный major
диапазон, поэтому её нужно пересмотреть и удалить после обновления зависимости
в самом typescript-eslint. Глобальная замена остальных версий minimatch не выполнена.

## Проблемы прикладного API, которые остаются

Проверка включала чтение обработчиков и локальный вызов с подставными
переменными окружения и полностью замоканным `fetch`. Реальные токены не
использовались, запросы в YCLIENTS не отправлялись, бонусы и клиенты не изменялись.
Фактическая доступность этих маршрутов на production за внешним proxy не проверена.

### P0 — выдача административного токена без авторизации

Источник: `app/api/yclients/token/route.ts:37`.

`GET /api/yclients/token` использует административные реквизиты из окружения,
если в запросе нет логина и пароля, и возвращает `user_token` любому вызывающему.
Кэш токена общий для всех запросов: даже запрос с другими реквизитами получает
ранее сохранённый токен. Пароль также принимается в query string.

Подтверждено локально: запрос без Cookie/Authorization получил HTTP 200 и
подставной административный токен; второй запрос с другими реквизитами получил
тот же кэшированный токен без повторной авторизации.

Необходимо убрать публичную выдачу токена, перенести получение токена в
серверный сервис и проверять административную сессию в каждом использующем его
обработчике. Если маршрут был доступен публично, отозвать выданные токены и
проверить журналы доступа после ограничения доступа.

### P1 — произвольное начисление бонусов

Источник: `app/api/yclients/loyality/add/route.tsx:7`.

Маршрут принимает `card_id`, `amount` и `title` от посетителя и выполняет операцию
с серверным `YC_USER_TOKEN`. Нет проверки сессии, владельца карты, допустимой
суммы и повторного начисления. Проверка `!amount` пропускает отрицательные
и произвольные ненулевые значения.

Подтверждено локально: запрос без авторизации передал произвольную сумму в
замоканный `manual_transaction` и получил HTTP 200.

Необходимо вычислять сумму и право на бонус на сервере, проверять владельца
карты, подтверждённое событие регистрации/визита и обеспечивать идемпотентность.

### P1 — доступ к клиентам и картам по произвольному телефону

Источники: `app/api/yclients/clients/route.ts:9`,
`app/api/yclients/loyality/cards/route.tsx:8`, `app/admin/page.tsx:10`.

Список клиентов запрашивается с административным токеном без проверки прав.
Карты ищутся по переданному `phone`; `full=true` возвращает весь объект карты.
Страница `/admin` также не проверяет роль. Данные из `localStorage` в интерфейсе
не являются серверной аутентификацией.

Подтверждено локально: без сессии получены подставные данные клиента и баланс
карты. Нужно ограничить список клиентов административной ролью, получать
телефон из проверенной сессии и возвращать только нужные поля.

### P1 — пересылка произвольных полей при регистрации

Источник: `app/api/yclients/clients/add/route.tsx:32`.

Обработчик копирует всё тело запроса и удаляет только `consent`, затем отправляет
его в YCLIENTS с серверными правами. Проверяет лишь непустые имя и телефон.
Клиент может передать дополнительные поля и произвольные `custom_fields`.

Подтверждено локально: поля `is_vip` и `custom_fields.bonus` дошли до замоканного
upstream. Примет ли конкретное поле реальный YCLIENTS, в этом аудите не проверялось.
Нужны схема с разрешённым списком полей, нормализация/проверка телефона,
ограничения размеров строк и серверное управление бонусными флагами.

### P2 — неподтверждённые webhook и незавершённая интеграция

Источник: `app/api/yclients/webhook/visit/route.ts:4`.

Обработчик не проверяет отправителя и защиту от повторной доставки, доверяет
`payment_status` из тела. В URL и заголовках оставлены `{company_id}` и `{TOKEN}`.
Подтверждено локально: неподписанный запрос достигает вызова внешнего API с этими
заглушками. Реальное успешное начисление через этот маршрут не подтверждено.

Перед включением интеграции нужны проверка подлинности webhook, повторная
проверка визита на сервере, идемпотентность и обработка неуспешных ответов API.

### P2 — токен пользователя в localStorage

Источник: `components/shared/login_form.tsx:60` и `:70`.

`user_token` сохраняется вместе с профилем в `localStorage`, доступном JavaScript
страницы, включая подключённые сторонние скрипты. Это увеличивает последствия
компрометации скрипта или XSS; наличие самой XSS в этом аудите не установлено.
Нужно хранить токен на сервере, использовать HttpOnly/Secure-сессию и обновить
проверки входа/выхода. Проверять права только на основании серверной сессии.

### P2 — отсутствуют ограничения запросов в коде авторизации и регистрации

Источники: `app/api/auth/login/route.tsx:9`, `app/api/yclients/auth/route.ts:5`,
`app/api/yclients/clients/add/route.tsx:21`.

В этих обработчиках нет rate limit или механизма ограничения повторных попыток.
Нужны общие ограничения по сессии/учётной записи/IP и защита регистрации от
автоматических повторов. Наличие ограничений на внешнем proxy не проверялось.

## Дополнительные исправления

- Удалено логирование административного токена, полного списка клиентов и
  исходного тела webhook. Это не устраняет проблемы авторизации маршрутов.
- Инициализация регистрации перенесена в `useRegistrationContext` на основе
  `useSyncExternalStore`: совместима с SSR, обрабатывает повреждённое или
  недоступное локальное хранилище, убирает ошибку `react-hooks/set-state-in-effect`.
- Добавлены команды `npm run typecheck` и `npm run audit`.
